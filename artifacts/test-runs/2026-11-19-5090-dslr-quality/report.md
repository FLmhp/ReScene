# RTX 5090 DSLR 三路线质量优先实验

实验使用同一 RTX 5090 克隆实例，总显存 32,607 MiB。实现从 `6fef737` 开始，单线程冷启动试验使用 `ea5bcee` 对应的隔离源码。共享盘归档根目录为 `/root/autodl-fs/rescene/experiments/dslr-quality-56235`。本轮实际模型、逐图数据及超时与失败记录以该归档为准。

## 数据与验收口径

- 开发场景为 `office`（26 张）和 `courtyard`（38 张）。冻结全部原图 SHA-256 和 8 张验证图，保留模糊或疑似重复的可解码素材。新下载的 `kicker`（31 张）和 `terrace`（23 张）作为独立验收，图像、标定和扫描归档通过 7-Zip 完整性及 SHA-256 校验。[ETH3D 数据与许可](https://www.eth3d.net/)
- 验证图可参与位姿求解，全部从 3DGS 优化集排除。各方案按同一源图的固定尺寸统计 PSNR、SSIM 和 LPIPS。初筛要求至少 7 张共同支持图，晋级要求 8 张。F1 使用官方评估器在 2 cm 容差下计算。
- 官方标定 MVS 先验证输入与扫描坐标的一致性。共享 `PINHOLE` 只适用于单一官方内参组且规范化尺寸一致的图集。检查得到 `office` 满足条件，`courtyard` 的四组标定与不同图像尺寸使其不适用。
- 完整对照维持既有输入尺寸、依赖、架构和锁。单阶段复用统一稀疏模型的 SHA-256；完整耗时从冷启动流水线计算。使用已冻结规格区分阶段复用、冷启动和多相机标定诊断。

## 本地验证与 GPU 冒烟

Python 测试通过 238 项，跳过 9 项。Ruff 检查、格式检查和 API schema 的 mypy 通过。在本轮隔离源码上，Golden Kitchen FAST 100-step 冒烟通过，checkpoint 步数为 `99`，PLY 与 SPZ 均可重载。完整 Golden Kitchen 三条历史基线来自同一克隆。[同实例完整三路线记录](../2026-11-18-5090-full-three-routes/report.md)

## 室内外参考与盲重建

| 场景 | 官方标定 MVS F1（2 cm） | QUALITY 盲重建 F1（2 cm） |
| --- | ---: | ---: |
| office | 36.9071% | 28.0196% |
| courtyard | 52.9841% | 29.7436% |

室内 `office` 的 FAST 基线完成 7,000 步和 8 张渲染，只有 5 张验证图具备稀疏点支撑，耗时 186.34 秒。BALANCED 基线在原始 BA 失败后，用 16 个查询帧和最多 2,048 个查询点重试 VGGT，最终 PSNR 16.4235 dB，耗时 464.64 秒。两条均作为不可用基线记录。QUALITY 盲重建通过 8/8 验证，耗时 971.50 秒，PSNR 16.2152 dB。

室外 `courtyard` 的 FAST 基线注册 38/38 张，8 张验证图均完成渲染，稀疏点覆盖为 4/8，耗时 202.75 秒。BALANCED 同样通过 16 个查询帧的 VGGT 重试完成，耗时 737.63 秒。QUALITY 盲重建通过 8/8 验证，耗时 1,375.85 秒，PSNR 20.6200 dB。

## FAST 网格采样

| 场景 | 基线 → 网格采样稀疏点覆盖 | 网格采样 PSNR / SSIM / LPIPS | 网格采样耗时 | 峰值显存 |
| --- | --- | --- | ---: | ---: |
| office | 5/8 → 8/8 | 16.1547 / 0.7622 / 0.4189 | 177.23 s | 10,444 MiB |
| courtyard | 4/8 → 8/8 | 16.1162 / 0.4570 / 0.5095 | 207.28 s | 27,540 MiB |

两次都完成 7,000 步，checkpoint、PLY 与 SPZ 通过重载。室外候选峰值显存比基线增加 15,486 MiB，保留 5,067 MiB。两条原始 FAST 基线均未达到最小覆盖，记录为可用性恢复。

固定已恢复的稀疏模型，`office` 训练从 129.750 秒降至 122.507 秒（−5.6%），`courtyard` 从 149.606 秒降至 122.253 秒（−18.3%）。两组均在 8 张图通过设定的光度容差。

重新冷启动网格采样并运行 6,000 步后，两个场景仍有 8/8 张验证图得到支持。`office` 全程耗时 155.748 秒，LPIPS 超出容差。`courtyard` 全程耗时 178.884 秒，PSNR 从 16.1162 降到 15.1009 dB，LPIPS 同样越界。因此保留 7,000 步作为本轮恢复案例的设置。

## BALANCED 覆盖查询与观察点分块

第一次覆盖查询在 DINO 的 BFloat16 距离矩阵转 NumPy 时失败。适配层现先转 Float32，随后执行同一选择算法。原失败保留，单独重跑目录以后缀 `quality-rescreen-s42` 标识。实际 RTX 5090 环境的 CPU PyTorch 已测试 BFloat16 转换。

65,536 观察点对照均通过 16 个查询帧的 VGGT 重试完成。与各自基线相比，`office` 的实际流水线耗时为 422.77 秒（基线 464.64 秒），`courtyard` 为 665.84 秒（基线 737.63 秒）。进入 BA 时 PyTorch 分配峰值分别仍为约 5,143 和 5,287 MiB，完整进程树峰值反而升至 15,526 和 28,598 MiB。以上数据属于 VGGT 重试记录，尚无有效的原生 BALANCED 配对证据。

修复后的覆盖查询分别用 445.631 秒和 642.367 秒完成两场景，原 8 查询帧的 BA 仍失败，两条均重试到 16 帧。此条件下没有启动 20k 对 16k 的比较。可用性与原生路线耗时分开统计。

## QUALITY 共享内参与 MVS

`office` 共享 `PINHOLE` 盲建图仅注册 21/26 张，`DSC_0237.JPG`、`DSC_0240.JPG` 两张冻结验证图缺失。MVS 生成了 173,302 个融合点，3DGS 训练在 6/8 验证覆盖处停止。该候选未取得可用的完整评分。按相机组前置条件，`courtyard` 继续使用原相机模式。迭代数对照固定各自通过 8/8 的原始稀疏模型。

| 同一稀疏模型 | PatchMatch + 融合 5 次 → 3 次 | 2 cm F1 5 次 → 3 次 |
| --- | --- | --- |
| office | 475.323 → 297.299 s（−37.5%） | 28.0196% → 27.3787%（相对 −2.3%） |
| courtyard | 682.486 → 437.952 s（−35.8%） | 29.7482% → 29.1879%（相对 −1.9%） |

同模型复测的 `courtyard` 5 次迭代 F1 为 29.7482%，与原完整冷启动的 29.7436% 相差 0.0046 个百分点。两组阶段对照均通过 5% F1 容差并进入冷启动。

| 首轮冷启动 | 原流水线 → 3 次迭代 | 2 cm F1 |
| --- | --- | --- |
| office | 971.499 → 657.669 s（−32.3%） | 28.0196% → 13.9053% |
| courtyard | 1,375.854 → 1,012.980 s（−26.4%） | 29.7436% → 30.7887% |

完整冷启动中 `office` 的 F1 回退显著高于固定稀疏模型时的差异。这一轮完整结果拒绝晋级。已从 PyCOLMAP 4.2.1 核实匹配几何验证和增量建图有独立种子字段。修正后独立归档和验证实验复现性，再决定是否完成带显式种子的三次冷启动配对。[COLMAP 增量建图源代码](https://github.com/colmap/colmap/blob/main/src/colmap/controllers/incremental_pipeline.cc)

显式种子配合默认多线程时，两场景的两个稀疏结果都完全注册，四个模型文件仍有不同的 SHA-256。第二轮限定特征、匹配、增量建图和末次 BA 的线程数为 1，GPU MVS 和训练维持原设置。两次从图片冷启动所得的稀疏文件在各场景内逐一匹配 SHA-256，注册数为 26/26 和 38/38。后续冷启动配对使用这套稀疏线程设置，相关开销计入全程。

| 单线程稀疏、种子 42 | 全程 5 次 → 3 次 | 2 cm F1 | PSNR |
| --- | --- | --- | --- |
| office | 853.465 → 674.957 s（−20.9%） | 21.5798% → 21.0090%（相对 −2.6%） | 16.0772 → 15.7422 dB |
| courtyard | 1,236.340 → 1,007.285 s（−18.5%） | 30.5465% → 30.2174%（相对 −1.1%） | 20.2639 → 20.3616 dB |

两场景均保留 8/8 张受支持的验证图，PatchMatch 加融合分别缩短 37.4% 和 36.3%。`courtyard` 通过本次质量和提速门槛。`office` 两轮规范化输入的 SHA-256 一致，点云对齐矩阵相同，相机 ATE 均为 0.03031 m。训练均从稀疏点初始化，最终 Gaussian 数分别为 463,871 和 482,691。其 PSNR 与 LPIPS 均超出容差，现有结果无法将全程渲染差异归因到 MVS 迭代数本身。

## 晋级判定与环境恢复

三条路线均未达到晋级条件，生产默认配置保持原值。`kicker` 和 `terrace` 的图像与扫描压缩包通过完整性与 SHA-256 校验，保留为独立验收集。种子 43/44 的配对、独立场景评分及候选版本的图片、视频、OSS 发布和 Viewer 回归均未触发。

5090 共享盘归档位于 `/root/autodl-fs/rescene/experiments/dslr-quality-56235`。归档校验复算了 13 份运行清单中的 264 个文件的 SHA-256，配对结论保存在 `seeded-serial/confirmation-summary.json`。实验结束后恢复生产 Worker，状态 API 返回 HTTP 200，检测到 1 台在线 Worker。

本地 CPU 验证结果为 238 通过、9 跳过。Ruff 检查、格式校验与 API Schema 的 mypy 检查均通过。
