## 实施顺序

- 首批建议 A01–A05。A01 与 A02 可并行。A03 与 A04 共用 API 数据层，落地时需协调迁移编号和并发夹具。A05 可独立与应用代码并行，完成隔离演练后再把脚本用于候选交付。
- A02 与上一轮 001、005 共用客户端文件。A03、A04、A08、A09 与 001、003 有 API 文件重叠。先确定集成基线，再重查锚点与迁移编号。A04 的原生项目重放、A07 的本地文件生命周期以 005 所含的账户隔离和队列写入语义为基础。
- A06 与 A23 可以独立验证，前者处理评估证据保存，后者处理计算输入。A10 与上一轮 #9 可分别验证，涉及同一事件流，集成时共同校验回退和权限。
- A13 与 A27 涉及同一试验监督脚本，可以共用进程归属、启动中断和恢复的验收夹具。

## 产品方向

- **5090 克隆验收记录（S–M）**。汇总运行身份、锁与 Worker 状态、一个小型真实任务和回滚记录。复用 `workerctl`、运行包校验和现有验收材料，降低切换时反复核对的成本。最初保持为运维入口，不需要后台页面。 [克隆验收步骤](../docs/单5090系统部署与运维.md#L243) · [运行包校验](../scripts/runtime_bundle.sh#L21)
- **原生端离线传输列表（M）**。列出当前账户等待连接、需重选文件和可取消的上传，先打通一个平台的完整恢复，再验证另一端。它依赖 A07 定义本地文件的所有权和寿命。 [Android 当前队列消息](../apps/mobile/src/screens/Project.tsx#L137) · [微信当前队列消息](../apps/miniapp/src/pages/project/index.tsx#L305)
- **桌面场景缓存占用与清理（M，先测量）**。场景缓存按重建产物保存并核验哈希，可先测常用场景占用，再验证手动清理和同一 scene 正在打开时的行为。 [用户手册](../docs/用户手册.md#L132) · [缓存目录](../apps/desktop/src-tauri/src/lib.rs#L15)
