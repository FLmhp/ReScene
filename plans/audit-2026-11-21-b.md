# ReScene 第三轮深度审计（2026-11-21）

基线为 `8c6009c`（`0.4.1`，001–032 已合并）。本轮只做只读审计：覆盖 Python API/Worker/引擎、四端客户端、共享包、测试、CI、发布与运维脚本。未重新运行测试、构建、Docker、GPU、真机或生产操作；上一轮用户确认的验收结果不作为本轮实测。

本轮结论：001–032 的主体实现成立，但仍有 4 类可直接影响线上安全、数据完整性或 GPU 成本的问题：

1. 匿名接口的限流键可被 `X-Forwarded-For` 绕过，且限流器永不清理键。
2. API 没有请求体上限；单个未认证请求可耗尽 640 MB 容器。
3. 原生上传把任何 `409` 都当作“服务端已拥有该上传”并从队列丢弃；其中包含可重试的“上传未完成/大小或哈希不匹配”，会静默丢失用户文件。
4. 上传会话先提交素材行再取 STS；STS 失败会留下不可恢复的孤立 `UPLOADING` 行。

其余高价值问题集中在：重试任务的进度残留、过期上传清理阻塞 GET、Android 并发上传的磁盘峰值、桌面分享二维码被 CSP 拦截、通知面板不再拉取新通知、任务恢复覆盖评估证据、OOM 降级不随 checkpoint 恢复、以及契约/CI 没有真正验证跨层一致性。

## 安全

| ID | 发现 | 证据 | 影响 |
|---|---|---|---|
| SEC-01 | 限流键由客户端控制，且键永不淘汰 | `infra/api/Dockerfile:11` 把 Uvicorn 的 `--forwarded-allow-ips` 设为 `*`；`src/rescene_api/main.py:93` 用 `request.client.host:path` 作键；`src/rescene_api/ratelimit.py:17` 只增不清 | 轮换 `X-Forwarded-For` 即可无限猜密码/注册；每个伪造键永久占用进程内存 |
