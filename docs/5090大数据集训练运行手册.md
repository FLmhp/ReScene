# RTX 5090 大数据集训练运行手册

状态为待执行。实例关机时只维护文档和离线开发。开机后使用 30 GPU 小时，测量更多场景和更完整的视角覆盖。每个场景独立优化 3D Gaussian，VGGT 使用锁定的预训练模型。生产 Profile 在完成晋级评审前维持现有参数。

## 1. 环境、目录与容量

登录后核对实例 GPU 名称、实际总显存、驱动、CUDA runtime 和 PyTorch Compute Capability。确认 gsplat 扩展支持 `sm_120`，记录 VGGT 权重、gsplat 扩展文件、第三方源码、环境锁和 Git 提交的 SHA-256 或 Git SHA。重新使用克隆实例时，先核对挂载与私有运行环境，再检查 `/root/ReScene/workerctl status`。

| 位置 | 用途 | 上限或门槛 |
|---|---|---:|
| `/root/autodl-fs/rescene/datasets` | 下载包、许可、内容清单及真值包 | 45 GB |
| `/root/autodl-fs/rescene/runtime-bundles` | 离线安装包、模型与版本清单 | 20 GB |
| `/root/autodl-fs/rescene/experiments/<suite-id>` | 冻结计划、试验指标、选定产物 | 65 GB |
| `/root/autodl-fs/rescene/staging` | 下载临时文件、上传未完成归档 | 20 GB |
| `/root/autodl-tmp/rescene/large-scenes/<suite-id>` | 单场景解包、运行输出和临时缓存 | 开跑前可用 ≥10 GiB 且 ≥本次预计写入的 1.3 倍 |

ReScene 的共享盘预算合计 150 GB，账户额度为 200 GB。每批次先用 `mountpoint -q /root/autodl-fs` 验证确实挂载，再用 `findmnt --target /root/autodl-fs`、`df -h /root/autodl-fs /root/autodl-tmp` 和控制台实际配额确认空间。共享盘保留冷数据，本地盘只展开当前场景，阶段产物先写本地。估算缓冲包含解包、去畸变、COLMAP MVS 临时文件、Gaussian checkpoint 和最终 PLY/SPZ。挂载缺失、预测空间不足或任一哈希校验失败即停止本批次。

共享盘便于克隆实例间复用数据，热数据从本地盘读取。把可再下载的源文件保留成归档，避免同时积压解包版本。生产素材及交付产物仍由 OSS 管理。[AutoDL 文件存储说明](https://api.autodl.com/docs/fs/)

## 2. 数据与冻结清单

| 数据 | 开发组 | 留出组 | 用途 |
|---|---|---|---|
| Golden Kitchen | 固定历史清单 | 无 | 校验环境与三条路线，复测历史基线 |
| ETH3D Low-res many-view | `delivery_area`、`playground` | `terrains`、`forest` | 室内外规模、几何及注册率验证 |
| Mip-NeRF 360 | `room`、`garden` | `counter`、`treehill` | 检查高分辨率细节及不同视角轨迹 |

ETH3D 优先取官方去畸变图、评测真值和遮挡包。已有同物理场景的历史版本属于开发组，包括换相机或分辨率的版本。执行前确认两个候选留出场景均无参数筛选记录。如果某个场景已用于调优，先在保留来源中按字典序选择一个从未用于调优的同类场景并记录理由。若缺少合规的室内或室外替代场景，该路线只报告探索结果。Mip-NeRF 360 在资料使用条件确认后缓存官方两部分下载包及其条款。条件未确认时跳过，时间留给 ETH3D。原图和真值只保存在授权环境。[ETH3D 官方数据](https://www.eth3d.net/datasets) · [Mip-NeRF 360 官方下载](https://jonbarron.info/mipnerf360/)

1. 每个下载包先写 `.partial`。校验发布方提供的摘要，再记录本次 SHA-256、字节数、下载 URL、使用条件和归档日期。通过后在同一挂载点原子改名。
2. 按时间戳和相机编号排序，稳定规则的平局使用相对路径。多相机数据先按物理时间组分区，再在各区轮换相机。素材清单记录相对路径、哈希、相机、时间、尺寸和来源。
3. 对每场景预先固定 8 个覆盖全轨迹的验证视图，取 8 个等长时间段中部的合格视图。先基于原图质量校验可读性、严重模糊和重复，禁止根据路线是否注册成功选择验证视图。用 `discover_images()` 的确切排序把路径转换成试验规格 `validation.sources` 的下标，并记录对应来源 ID。小型 Golden Case 沿用已冻结的验证来源。
4. 生成嵌套的 80、160、250 帧输入清单，帧上限包含验证图。先填 80 帧，从剩余帧均匀补到 160 和 250。各输入子集均包含同一验证图。FAST 覆盖优先候选在同一组时间段内优先选择清晰图，拒绝与前一入选图近重复的候选，再以相对路径排序破同分。均匀对照在每段取中间合格帧。冻结规则、清晰度和重复阈值在开发组基线前记录。
5. 保存每个输入子集和采样规则的 SHA-256。验证图可参与几何估计，从 Gaussian 优化保留出来。报告明确采用这一评测口径。某个视图未注册时记录失败，保留现场证据。

## 3. 开机、运行与恢复

1. 开机前先确认维护窗口。开机后完成挂载、环境、配额、源哈希检查，确保只运行一个实验批次。等待活动任务结束，确认 Worker 为空闲的 `running drain=no`。以正常模式启动监督器，由它负责 drain、stop，并通过 `flock --close` 获取 `/root/ReScene/.gpu.lock`。发现外部 GPU 计算进程则暂停，忙闲判断以 compute PID 为准。
2. 每个批次使用独立的 `suite-id`，用 `RESCENE_DELIVERY_ROOT` 把工作目录指向本地数据盘。沿用 `scripts/route_experiments_v3.py` 的 JSON 单试验规格及 `scripts/supervise_route_experiments.py` 的 JSON 计划。每条规格显式写 `scene`、`scene_id`、`candidate_id`、`profile`、`frame_limit`、`validation.sources` 和 `overrides`。批次计划逐项列 `name`、`spec`、`repeat`。
3. 开跑前在实验分支补齐两处运行器支持。现有运行器成功后会清理 `gsplat/ckpts`，须先归档或保留基线及最终候选的最后 checkpoint。为有界试验增加总预算和按体量检查磁盘的门槛，30 小时与本地空间限制在每条试验前检查。校验 CPU 试验计划、目录解析和漏帧拒绝路径通过后再跑 GPU。
4. 用 `nohup` 从登录会话启动监督器并记录 PID 与日志路径。每次仅跑一个场景，使用 12 核上限，耗时采样期间暂停 CPU 密集几何评测。坏输入、可比较性失败与系统异常分别落盘。只有输入、配置、阶段产物校验一致时才恢复成功阶段。OOM 降级按现有一次有界策略保留处置证据，结果排除在候选对照之外。
5. 夜间无人值守前验证中止与恢复路径。预算结束或失败时只停止本次进程树。确认锁释放后恢复 Worker，检查 `drain=no`、心跳和队列状态。登记恢复时刻、镜像或 runtime 摘要及剩余预算。

完成上述启动检查和运行器准备后，从 `ReScene` 根目录按实际批次名启动。`specs/plan.json` 和输出目录预先生成和校验。

```bash
export RESCENE_DELIVERY_ROOT=/root/autodl-tmp/rescene/large-scenes/manyview-v1
nohup .venv/bin/python -u scripts/supervise_route_experiments.py \
  "$RESCENE_DELIVERY_ROOT/specs/plan.json" > "$RESCENE_DELIVERY_ROOT/launcher.log" 2>&1 </dev/null &
echo "$!" > "$RESCENE_DELIVERY_ROOT/launcher.pid"
```

| 时段 | 顺序与参数 |
|---|---|
| 0–3 小时 | 完成 CUDA、VGGT、PyCOLMAP、gsplat 和 SPZ smoke，先跑 100-step 后跑 Golden Kitchen 的 FAST、BALANCED、QUALITY 各一次。 |
| 3–12 小时 | 在 ETH3D 两个开发场景逐路线生成当前基线。FAST/BALANCED 为 80 帧，QUALITY 单独对照固定验证集下的 160 与 250 帧。室内外完成后用余量跑 Mip-NeRF 360 开发组。 |
| 12–24 小时 | FAST 固定 7k 步比选帧，BALANCED 固定 80 帧和 20k 步对照查询帧 8 与 12，QUALITY 固定 20k 步、`SIMPLE_RADIAL` 与帧清单对照原 MVS 分辨率和 1200 px。单次筛除回退者，每路线最多一个候选，按同一场景和规则补足基线与候选的三次配对。 |
| 24–30 小时 | 冻结候选后依次验证室内、室外留出组，空闲时评估 QUALITY 点云。至少预留最后 30 分钟完成归档与 Worker 恢复。 |

预算不足时优先完成 ETH3D 室内外、可比较的配对及 Worker 恢复。Mip-NeRF 360 和新增候选可顺延。记录各阶段耗时、读写速率、CPU/RSS、进程树显存和单场景写入峰值。优先分析计时和资源瓶颈，再调整一个变量。

## 4. 证据和晋级

- 每次归档 `input_manifest.json`、环境锁、最终配置、阶段日志、`metrics.json`、校验结果和逐视图渲染指标。基线及最终候选另存最终 checkpoint、PLY、SPZ，验证可重载、大小与 SHA-256。写入共享盘暂存目录并校验，通过后改名再清理本轮登记的本地缓存。
- 冻结验证图必须全部注册，PSNR、SSIM、LPIPS 均需为有限值。评测统一像素尺度。按场景列出注册率、BA 前后重投影误差、显存及训练和端到端耗时。质量容差分别为 PSNR −0.20 dB、SSIM −0.01、LPIPS +0.01。显存至少留出 3 GiB。三次配对的中位数与范围必须一起报告。
- FAST 在质量容差内至少提速 15%。BALANCED、QUALITY 至少实现 PSNR +0.50 dB、SSIM +0.02、LPIPS −0.05 中一项，总耗时不超过同场景基线的 1.5×、2×。QUALITY 在适用的 ETH3D 对齐与遮挡协议下同阈值计算点云 F1，相对回退不得超过 5%。无真值场景只记录光度等可测指标。
- 由报告列出晋级、失败和样本不足三类结论。候选通过开发组重复、室内外留出组与导出校验后再进入发布评审。生产默认参数改动单独提交。
