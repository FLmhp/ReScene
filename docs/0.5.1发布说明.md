# ReScene 0.5.1

[0.5.1 已在公开 GitHub Release 发布](https://github.com/FLmhp/ReScene/releases/tag/v0.5.1)，对应 tag `v0.5.1`（合并提交 `73d19fc`）。[一次完整运行](https://github.com/FLmhp/ReScene/actions/runs/45049778199) 同时完成构建、部署与发布：四个桌面安装包、签名 Android APK、生产部署和 GitHub Release 都由该运行产出，`release-log.json` 记录产物哈希、镜像摘要与部署结果。首轮发布用的是手工构建的资产，本轮由公开仓库的 GitHub 托管运行器重新构建，安装包哈希与首轮不同，以本文校验值为准。

## 账号安全

- 登录页新增邮箱验证码登录与忘记密码。验证码 6 位、10 分钟有效、一次性使用、最多 5 次尝试；同一账号 60 秒冷却、每小时最多 5 封，未注册邮箱与已注册邮箱返回相同响应。整条逆链 `401 invalid_code`，尝试次数耗尽返回 `429`，客户端锁定 5 分钟。
- 密码重置撤销全部旧会话与未使用验证码，并直接返回新登录令牌。数据库迁移至 `0011`，只保存验证码的 HMAC-SHA256 摘要；未配置 SMTP 时生产环境返回 202 但拒绝投递，开发环境把验证码写入 API 日志。
- 四端登录页统一为图标与 `ReScene` 居中、标题「验证码登录」；Web、Android、小程序均可从密码登录切换到验证码登录并返回。

## 外观

- 配色预览改为圆角色块加主色调，传统方案更名为青瓷素影、群青远山、墨染松烟、胭脂海棠、朱砂落印、赭石秋峦、靛青夜泊，自定义改为自定主色。未保存过偏好的设备默认跟随系统并使用群青远山。
- Web、桌面、Android 和微信小程序共用同一套设计令牌与配色名称。明暗、配色、字号与面板效果仍按设备保存，退出登录后保留，主题切换不影响上传队列与表单。

## 生产部署

- 本轮改由 [release.yml](.github/workflows/release.yml) 的 `deploy` job 自动完成：从 `v0.5.1` 的 tag 源码在主机上重建两个镜像，`rescene-api:0.5.1` 为 `sha256:223eeeb40f704b71eeb82c176db2532eb036130b12b0c1acf116db2cbcb1ad42`，`rescene-web:0.5.1` 为 `sha256:7db04d717fe1766d8a6447410be93f3abc4129d4adc425acb047a259e68f9e4d`。上一轮手工部署的镜像为 `f99b6fcc…` 与 `3c34849d…`。
- 切换前把配置与镜像记录备份到 `/root/rescene-backup-0.5.1-20261122T173431Z`，数据库备份为 `/opt/rescene/infra/backups/rescene-pre-deploy-0.5.1-20261122T173431Z.dump`（SHA-256 `44a64cfb2af92180a800c321debf9d1fae75de263f2d7713fe18436308a169a5`，脚本内已用 `pg_restore --list` 校验）。只重建 `api` 与 `web` 容器，数据库保持运行；API 启动时迁移到 `0011`。过程记录在 `release-log.json` 与 `deploy-log.json`。
- 公网探针由工作流在部署后自动执行：Web `200`，`/health/ready` `200`，未注册邮箱请求验证码 `202`，登录接口对无凭据请求返回 `401`；三段结果写入 `deploy-log.json`。响应头包含 `x-frame-options: DENY`、`x-content-type-options: nosniff`、`referrer-policy: strict-origin-when-cross-origin` 与 HSTS。库内现有 18 个项目、131 个素材。
- 上一轮部署时发现主机 `/opt/rescene/infra/compose.yaml` 还是 0.5.0 的副本，未透传 `RESCENE_ENV` 与 `RESCENE_SMTP_*`，API 实际以开发模式运行并把验证码写进日志。已同步仓库的 0.5.1 compose 并设置 `RESCENE_ENV=production` 后重建 API，重启后日志只记录「验证码已丢弃」，不再输出验证码。
- 主机仍没有 SMTP 凭据，生产环境请求验证码会安全地返回 202 但不会投递。配置 `RESCENE_SMTP_HOST/PORT/SECURITY/USERNAME/FROM/PASSWORD` 后重启 API 才会真正发信。

## 已知限制

- 当前发布流程没有商业代码签名证书，Windows SmartScreen 会提示未知发布者。macOS 产物未签名、未公证。
- Linux 与 macOS 只记录 CI 构建结果，本机不安装。构建成功不等于平台安装验收完成。
- 本机 Windows 的 Android 原生构建需要把 CMake 暂存目录放到短路径（`scripts/android-windows-cmake.init.gradle`），并给所有原生模块加 220 字符对象路径上限；仓库路径较深时旧脚本无法完成 `expo-modules-core` 与 `react-native-webview` 的编译。该修复不影响已发布的安装包内容。
- 历史验收截图和报告没有随仓库公开，仓库内只保留文档与摘要；需要原始截图时按提交从本机归档查找。
- 0.5.0 与 0.4.1 的验收不能替代 0.5.1 的构建、真机和生产检查。

## 未覆盖的场景

- 生产 GPU Worker 不在线（`rescene-worker` 未运行），本轮没有提交重建任务，渲染链路沿用在 0.5.0 的验证结果。
- 生产 SMTP 未配置，验证码登录与密码重置在公网只能返回 202，不会投递；投递与失败路径已用同一镜像在本机真实 SMTP 验证。配好 `RESCENE_SMTP_*` 后需要再跑一次真实收件确认。
- 微信小程序只做了类型检查与构建，没有上传开发版或体验版，没有用真机验证验证码登录。
- Linux `.deb`、Linux `.AppImage`、macOS `.dmg`、Windows 安装包与本轮 CI 构建的 Android APK 均未做本机安装实测；Android 只验证了签名证书、`versionName`/`versionCode` 与 `arm64-v8a` ABI。
